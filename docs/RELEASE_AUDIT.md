## 3. Dependency hazard found during this audit (fixed)

`opencv-python-headless>=4.8` was **not safe to install**: the spec resolved to
`opencv-python-headless 5.0.0.93`, and OpenCV 5.x no longer provides what this
project's face path needs.

Evidence (all commands in §12):

| observation | result |
| --- | --- |
| wheel `opencv_python_headless-5.0.0.93` file list | 40 `cv2/` entries, **no** `cv2/data/*.xml` (only `cv2/data/__init__.py`) |
| installed 5.0.0 in an isolated venv | `cv2.data.haarcascades` exists but the cascade file does **not** |
| project call `build_cascade(config.face)` on 5.0.0 | `AttributeError: module 'cv2' has no attribute 'CascadeClassifier'` |
| wheel `opencv_python_headless-4.14.0.94` file list | contains `cv2/data/haarcascade_frontalface_default.xml` (18 files under `cv2/data`) |
| installed 4.14.0 (with the pin) | `cv2.__version__ = 4.14.0`, cascade present, `CascadeClassifier` available |
| validated development environment | `opencv-python 4.13.0.92`, `cv2/data` holds 17 `haarcascade_*.xml` (from its `RECORD`) |

Consequence without the fix: a new user would clone the repository, install the
documented requirements, and **every face input would fail** before inference —
the Quick Start would be broken on a clean machine.

Action taken: `opencv-python-headless>=4.8,<5` in `requirements/runtime.txt`,
`requirements/dev.txt` (inherits), `requirements/research.txt` (inherits) and
`pyproject.toml`, with an explanatory comment in the requirement file. The code
was **not** changed: it keeps loading the cascade from the installed OpenCV
package, exactly as the audited original did.

Residual: the pin is a maintenance obligation. When OpenCV 6/5.x is adopted, the
cascade must be shipped or fetched explicitly (the configuration already accepts
an absolute `cascade` path, so `configs/default.yaml` can point at a vendored
file — but then that file's Intel/BSD-3 license header must be kept and the
attribution in `THIRD_PARTY_NOTICES.md` §2 applies).

### 3.2 Python floor found to be uninstallable (fixed)

`pyproject.toml` declared `requires-python = ">=3.10"`. The pinned runtime
dependency `onnxruntime==1.24.1` publishes wheels for **cp311, cp312, cp313 and
cp314 only** — there is no cp310 wheel (checked against the PyPI release
metadata; the package's own `requires_python` says `>=3.10`, so the metadata
alone would not have revealed it). A Python 3.10 user could therefore never
install the documented requirements.

Action taken: `requires-python = ">=3.11"`, the `3.10` classifier removed, and the
CI matrix is `3.11` + `3.13` — the floor is now enforced by CI instead of
asserted in metadata.

## 8. License decision

**Decision: MIT for the source code (`LICENSE`), plus a separate research/
evaluation notice for the trained parameters (`MODEL_NOTICE.md`). This is case
"B" of the project brief: permissive code license + an explicit model/data
notice — not a blanket "everything here is open source".**

Why MIT, and why not the alternatives:

* every third-party runtime dependency is permissive (MIT / BSD / Apache-2.0 /
  ISC / PSF), so a permissive outbound license is compatible and no relicense
  obligation is triggered;
* MIT is the shortest, most widely understood OSI-approved license, which suits a
  portfolio-scale research prototype and imposes no attribution bureaucracy on
  the user;
* **Apache-2.0 was deliberately rejected**: it grants an explicit patent license
  (§3). The Phase 0 audit flagged the fusion approach as possibly touching an
  institutional/IP question ("创新方案B" in the frozen legacy training script, see
  §10.5). MIT grants no patent rights, so the author's — or their institution's —
  position on that idea is left exactly as it was. If that question is ever
  cleared and a patent grant is desired, Apache-2.0 is a drop-in replacement of
  `LICENSE` plus one line in `pyproject.toml`;
* BSD-3-Clause: no advantage over MIT for this repository;
* GPL/AGPL: would restrict reuse of a study prototype for no benefit;
* CC0 / public domain: designed for data, not code; and it would purport to waive
  rights over material whose status is exactly what §5 is about;
* **no license at all** (the Phase 1 state): not open source; every user would be
  legally unable to reuse the code, which defeats the purpose of publishing it.

Scope of the MIT grant: the package, scripts, tests, configuration, documentation,
and the two generated example files. It does **not** cover `weights/`
(`MODEL_NOTICE.md`) or the third-party components (`THIRD_PARTY_NOTICES.md`).

## 9. Model release decision

**Decision: the nine artifacts in `weights/` are published, under the separate
research/evaluation terms of `MODEL_NOTICE.md`. They are *not* covered by MIT and
they are *not* unrestricted.**

| question | answer | basis |
| --- | --- | --- |
| Were any third-party pretrained weights used? | **No** | all three networks are defined in this repository and trained by its own scripts; `docs/MODEL_ARTIFACT_MANIFEST.md` records provenance per file |
| Did the author's own contribution dominate the training data? | **Yes** — the only *positive* identity is the author's own 5 photos + 10 clips | Phase 0 audit; `data/` is private |
| Did third-party data contribute? | **Yes** — 50 Olivetti/ORL images as negatives (research use, attribution required) | §5 |
| Do the parameters reproduce the dataset? | **No** — they are 560 K trained parameters of a discrimination task; no image is reconstructible, and no dataset file is redistributed | architecture + `docs/MODEL_ARTIFACT_MANIFEST.md` |
| Is the legal status of weights trained on a research-use dataset *formally* settled? | **No — see §10.6** | no legal review was performed |
| Consequence | publish with an explicit notice, keep attribution, forbid commercial use, and say so in the README | `MODEL_NOTICE.md`, `THIRD_PARTY_NOTICES.md` |

Alternative considered and rejected: **withhold `weights/` entirely** (the brief's
option "模型权重暂不发布"). Consequences would have been: `scripts/infer.py`,
`scripts/benchmark.py` and `tests/test_artifacts.py` could not run, the Quick Start
would have no models to load, the published numbers would be unverifiable by any
reviewer, and the repository would degrade into an architecture-only sketch. Given
the provenance evidence above, a notice-limited publication is more useful *and*
more honest than a repository that claims to be runnable but ships no model.

Decision record in full: `docs/MODEL_RELEASE.md`.
